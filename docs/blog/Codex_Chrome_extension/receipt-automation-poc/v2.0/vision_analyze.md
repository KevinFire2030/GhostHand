# vision_analyze 쉽게 이해하기

이 문서는 Hermes Agent에서 사용하는 `vision_analyze` 도구가 무엇인지, 어떻게 동작하는지, 어떤 비전 LLM 모델을 쓰는지 초등학생도 이해할 수 있게 정리한 설명서입니다.

## 한 줄 요약

`vision_analyze`는 **이미지 파일을 AI에게 보여주고, 이미지 안에 무엇이 있는지 글로 설명하게 하는 도구**입니다.

예를 들어 영수증 이미지를 넣으면 AI가 이렇게 읽어줍니다.

- 이 영수증은 어느 가게에서 쓴 것인지
- 어떤 물건을 샀는지
- 총 얼마를 결제했는지
- 경비정산할 때 어떤 계정으로 처리하면 좋을지
- 왜 그렇게 판단했는지

## 쉽게 비유하면

`vision_analyze`는 **사진을 볼 수 있는 똑똑한 친구**에게 질문하는 것과 비슷합니다.

사람이 친구에게 이렇게 묻는다고 생각하면 됩니다.

> “이 영수증 사진 좀 봐줘. 어디서 얼마를 썼는지 읽고, 경비정산 계정도 추천해줘.”

그러면 친구가 사진을 보고 대답합니다.

> “스타벅스에서 커피와 베이글을 샀고, 총 13,500원이야. 회의용 음료와 다과로 볼 수 있으니 회의비가 좋아 보여.”

Hermes에서는 이 친구 역할을 `vision_analyze` 도구와 비전 LLM이 합니다.

## 이게 어떤 도구인지?

`vision_analyze`는 Hermes Agent의 **비전 도구**입니다.

여기서 “비전”은 눈으로 본다는 뜻입니다. 즉, 텍스트만 읽는 AI가 아니라 **이미지를 함께 볼 수 있는 AI**를 사용합니다.

`vision_analyze`가 할 수 있는 일은 다음과 같습니다.

- 이미지 설명하기
- 이미지 안의 글자 읽기
- 영수증, 표, 문서, 화면 캡처 분석하기
- 사진 속 물건, 장소, 상황 설명하기
- 사용자가 이미지에 대해 물어본 질문에 답하기
- 이미지 내용을 바탕으로 분류나 추천하기

이번 PoC에서는 `v2.0/sample` 폴더의 영수증 이미지를 읽고, 경비정산 계정을 추천하는 데 사용했습니다.

## 입력값은 무엇인가요?

`vision_analyze`는 보통 두 가지를 받습니다.

### 1. 이미지 경로 또는 이미지 URL

분석할 이미지입니다.

예시:

```text
/mnt/e/ax/PRJs/GhostHand/docs/blog/Codex_Chrome_extension/receipt-automation-poc/v2.0/sample/receipt_01_cafe_meeting.png
```

또는 인터넷 이미지 주소도 사용할 수 있습니다.

```text
https://example.com/receipt.png
```

### 2. 질문

이미지를 보고 무엇을 해달라는 요청입니다.

예시:

```text
이 영수증 이미지를 읽고 가맹점, 품목, 금액을 요약한 뒤, 계정_샘플.md에 있는 계정 중 하나를 추천해줘.
```

즉, 이미지만 던지는 것이 아니라 **이미지를 보고 어떤 일을 해야 하는지 질문도 같이 줍니다.**

## 출력값은 무엇인가요?

도구는 보통 이런 JSON 형태의 결과를 돌려줍니다.

```json
{
  "success": true,
  "analysis": "이미지 분석 결과 내용..."
}
```

- `success`: 성공했는지 여부입니다.
- `analysis`: AI가 이미지를 보고 작성한 설명입니다.

예시 결과는 이런 식입니다.

```text
가맹점: 스타벅스 강남역점
품목: 카페 아메리카노 Tall 2개, 치즈 베이글 1개
결제금액: 13,500원
추천 계정: 회의비
사유: 커피와 간단한 다과 구매 내역으로 회의 또는 업무 미팅 비용에 해당합니다.
```

## 어떻게 동작하나요?

전체 흐름은 아래와 같습니다.

### 1단계. Hermes가 이미지 위치를 확인합니다

먼저 이미지가 어디 있는지 확인합니다.

이미지는 두 종류일 수 있습니다.

- 내 컴퓨터에 있는 이미지 파일
- 인터넷에 있는 이미지 URL

이번 작업에서는 로컬 파일을 사용했습니다.

예시:

```text
v2.0/sample/receipt_01_cafe_meeting.png
```

### 2단계. 이미지가 진짜 이미지인지 확인합니다

Hermes는 파일이 실제 이미지인지 확인합니다.

지원하는 대표 형식은 다음과 같습니다.

- PNG
- JPG/JPEG
- GIF
- BMP
- WebP
- SVG

즉, 이름만 `.png`인 가짜 파일이 아니라 실제 이미지 파일인지 검사합니다.

### 3단계. 이미지를 base64로 바꿉니다

비전 LLM에게 이미지를 보내려면 이미지를 그냥 파일 그대로 보내는 것이 아니라, API가 이해할 수 있는 형태로 바꿔야 합니다.

Hermes는 이미지를 **base64 data URL** 형태로 바꿉니다.

쉽게 말하면:

> “이미지 파일을 아주 긴 글자 문자열로 바꿔서 AI에게 보낸다”

라고 생각하면 됩니다.

예시 느낌:

```text
data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA...
```

사람이 읽기 위한 글자는 아니고, 컴퓨터와 AI API가 이미지를 전달받기 위한 형식입니다.

### 4단계. 질문과 이미지를 함께 비전 LLM에게 보냅니다

Hermes는 비전 LLM에게 아래 두 가지를 같이 보냅니다.

- 사용자의 질문
- base64로 변환된 이미지

예시로는 이런 요청입니다.

```text
이 영수증 이미지를 읽고 핵심 내용과 추천 계정을 알려줘.
```

그리고 이미지 데이터도 함께 보냅니다.

### 5단계. 비전 LLM이 이미지를 보고 답합니다

비전 LLM은 이미지를 보고 다음을 추론합니다.

- 이미지가 영수증인지
- 가맹점명이 무엇인지
- 품목이 무엇인지
- 금액이 얼마인지
- 사용자가 물어본 기준에 따라 어떤 계정이 적절한지

### 6단계. Hermes가 결과를 받아서 다음 작업에 사용합니다

비전 LLM이 분석 결과를 돌려주면 Hermes는 그 내용을 받아서 문서에 정리하거나, 다음 판단에 사용합니다.

이번 작업에서는 분석 결과를 바탕으로 `계정 제안.md` 파일을 만들었습니다.

## 이번 PoC에서 실제로 어떻게 썼나요?

이번에는 다음 폴더의 영수증 이미지를 분석했습니다.

```text
v2.0/sample
```

이미지 예시:

```text
receipt_01_cafe_meeting.png
receipt_02_taxi_transport.png
receipt_03_office_supplies.png
...
receipt_10_equipment_purchase.png
```

각 이미지마다 이런 질문을 보냈습니다.

```text
이 영수증 이미지를 읽고 핵심 내용(가맹점, 품목, 금액)을 요약해줘.
추천 계정은 반드시 다음 목록 중 하나만 사용:
회의비, 국내교통비, 해외교통비, 접대비, 판촉비, 소모품비, 통신비, 교육훈련비, 출장숙박비, 소프트웨어구독료.
한국어로 계정과 사유를 작성해줘.
```

중요한 점은 **추천 계정 목록을 제한했다는 것**입니다.

그래서 AI가 마음대로 `복리후생비`, `지급수수료`, `비품구매` 같은 새 계정을 만들지 못하게 하고, `계정_샘플.md`에 있는 계정 중에서만 고르게 했습니다.

## 어떤 비전 LLM 모델을 쓰나요?

현재 이 환경에서는 `vision_analyze`가 Hermes의 **auxiliary vision 라우터**를 통해 모델을 자동 선택합니다.

현재 설정은 다음과 같습니다.

- `auxiliary.vision.provider`: `auto`
- `auxiliary.vision.model`: 비어 있음

즉, 설정 파일에 특정 비전 모델을 직접 고정해두지 않고, Hermes가 현재 사용 가능한 모델 경로를 자동으로 고릅니다.

이 환경에서 실제로 확인한 결과는 다음과 같습니다.

- **Provider:** `openai-codex`
- **Model:** `gpt-5.5`
- **Client:** `CodexAuxiliaryClient`

쉽게 말하면:

> 지금 이 작업 공간에서는 `vision_analyze`가 `openai-codex` 제공자의 `gpt-5.5` 모델을 사용해서 이미지를 분석했습니다.

## 항상 gpt-5.5만 쓰나요?

아닙니다.

`vision_analyze`는 Hermes의 설정에 따라 다른 모델을 쓸 수 있습니다.

Hermes의 비전 도구는 중앙의 auxiliary vision 라우터를 사용합니다. 이 라우터는 설정에 따라 아래 같은 제공자를 사용할 수 있습니다.

- OpenRouter
- Nous
- OpenAI Codex
- Anthropic
- OpenAI 호환 커스텀 엔드포인트
- 기타 Hermes가 지원하는 멀티모달 백엔드

그래서 다른 컴퓨터나 다른 Hermes 설정에서는 다른 모델이 선택될 수 있습니다.

예를 들어 설정을 바꾸면 다음과 같은 식으로 동작할 수 있습니다.

```yaml
auxiliary:
  vision:
    provider: openrouter
    model: google/gemini-3-flash-preview
```

또는:

```yaml
auxiliary:
  vision:
    provider: anthropic
    model: claude-sonnet-4-5
```

정리하면:

- 지금 이 환경: `openai-codex` + `gpt-5.5`
- Hermes 구조상 가능: 설정에 따라 다른 비전 모델 사용 가능

## 현재 모델 확인 방법

Hermes Agent 내부에서는 아래 Python 코드로 현재 비전 라우터가 어떤 모델을 쓰는지 확인할 수 있습니다.

```bash
/home/fireman_pro/.hermes/hermes-agent/venv/bin/python - <<'PY'
import sys
sys.path.insert(0, '/home/fireman_pro/.hermes/hermes-agent')
from agent.auxiliary_client import resolve_vision_provider_client
provider, client, model = resolve_vision_provider_client()
print('provider=', provider)
print('model=', model)
print('client_class=', type(client).__name__ if client else None)
PY
```

이번 환경에서 확인된 출력은 다음과 같습니다.

```text
provider= openai-codex
model= gpt-5.5
client_class= CodexAuxiliaryClient
```

## 이미지가 너무 크면 어떻게 되나요?

이미지가 너무 크면 API가 받지 못할 수 있습니다.

Hermes는 이런 문제를 줄이기 위해 몇 가지 안전장치를 둡니다.

- 다운로드 이미지 최대 크기 제한: 약 50MB
- 비전 API에 보내는 base64 payload 제한: 약 20MB
- 너무 크면 Pillow가 설치되어 있을 때 이미지 크기를 줄여서 다시 시도
- 그래도 너무 크면 오류 반환

초등학생 비유로 말하면:

> 너무 큰 그림은 편지봉투에 안 들어가니까, 그림을 작게 접거나 줄여서 보내는 것과 비슷합니다.

## 인터넷 이미지 URL을 쓸 때는 어떻게 되나요?

이미지가 인터넷 URL이면 Hermes가 먼저 이미지를 다운로드합니다.

그때도 안전 검사를 합니다.

- `http://` 또는 `https://` URL인지 확인
- 내부망/private 주소로 몰래 접근하지 못하게 검사
- 리다이렉트가 위험한 주소로 가는지 검사
- 웹사이트 접근 정책에 막힌 곳인지 확인
- 다운로드 후 임시 파일을 정리

즉, 인터넷 이미지를 처리할 때도 아무 주소나 무작정 열지 않고 안전 검사를 거칩니다.

## 로컬 이미지 파일을 쓸 때는 어떻게 되나요?

로컬 이미지 파일이면 다운로드하지 않습니다.

바로 그 파일을 읽어서 분석합니다.

이번 영수증 PoC에서는 로컬 파일을 사용했기 때문에 인터넷 다운로드 과정은 없었습니다.

예시:

```text
/mnt/e/ax/PRJs/GhostHand/docs/blog/Codex_Chrome_extension/receipt-automation-poc/v2.0/sample/receipt_01_cafe_meeting.png
```

## OCR과는 뭐가 다른가요?

OCR은 보통 **이미지 속 글자를 텍스트로 바꾸는 기술**입니다.

예를 들어 OCR은 이렇게 합니다.

```text
이미지 속 글자 → 텍스트
```

반면 `vision_analyze`는 글자만 읽는 것이 아니라, 이미지 전체를 보고 이해합니다.

예를 들어 영수증 이미지에서:

- 글자 읽기
- 금액 구조 이해하기
- 품목이 어떤 성격인지 판단하기
- 경비 계정 추천하기
- 추천 이유 설명하기

까지 할 수 있습니다.

그래서 `vision_analyze`는 단순 OCR보다 더 넓은 일을 할 수 있습니다.

단, 숫자나 작은 글자가 매우 흐리면 OCR 전문 도구보다 정확도가 떨어질 수도 있습니다. 그래서 중요한 업무에서는 이미지 분석 결과를 `.txt` 데이터, OCR 결과, 사람 검토와 함께 확인하는 것이 좋습니다.

## 장점

`vision_analyze`의 장점은 다음과 같습니다.

- 이미지 자체를 직접 볼 수 있습니다.
- 별도 OCR 파이프라인 없이도 영수증 내용을 읽을 수 있습니다.
- 사용자가 원하는 질문에 맞춰 답변할 수 있습니다.
- 단순 추출뿐 아니라 분류와 추천도 가능합니다.
- 로컬 파일과 인터넷 이미지 URL을 모두 처리할 수 있습니다.
- Hermes 도구 흐름 안에서 바로 문서 생성, 코드 작성, 파일 저장까지 연결할 수 있습니다.

## 주의할 점

`vision_analyze`도 완벽하지는 않습니다.

다음 경우에는 틀릴 수 있습니다.

- 이미지가 너무 흐림
- 글자가 너무 작음
- 영수증이 비뚤어져 있음
- 일부가 잘려 있음
- 표나 금액 구조가 복잡함
- 사용자가 계정 기준을 명확히 주지 않음

그래서 업무용 PoC에서는 다음처럼 쓰는 것이 좋습니다.

1. 이미지 분석으로 1차 추출
2. 같은 이름의 `.txt` 또는 OCR 결과로 보조 검증
3. 계정 후보는 사전에 정의된 목록으로 제한
4. 금액, 날짜, 가맹점명은 최종 제출 전 사람 검토

## 이번 경비정산 PoC에서 좋은 사용 방식

이 PoC에서는 아래 방식이 적절합니다.

### 1. 계정 목록을 먼저 정합니다

예:

```text
회의비
국내교통비
접대비
판촉비
소모품비
소프트웨어구독료
```

### 2. 이미지마다 같은 질문 템플릿을 사용합니다

```text
이 영수증 이미지를 읽고 가맹점, 품목, 금액을 추출해줘.
추천 계정은 계정_샘플.md에 있는 계정 중 하나만 골라줘.
추천 사유도 적어줘.
```

### 3. 결과를 Markdown으로 저장합니다

예:

```text
계정 제안.md
```

### 4. 애매한 경우에는 이유를 남깁니다

예:

```text
원본 힌트는 복리후생비이나, 계정_샘플.md에 복리후생비가 없으므로 회의비로 제안합니다.
```

이렇게 하면 나중에 사람이 왜 그 계정을 추천했는지 쉽게 이해할 수 있습니다.

## 아주 쉬운 전체 그림

```text
영수증 이미지
   ↓
vision_analyze 도구
   ↓
이미지를 AI가 볼 수 있는 형태로 변환
   ↓
비전 LLM에게 질문과 이미지 전달
   ↓
AI가 영수증 내용을 읽음
   ↓
가맹점 / 품목 / 금액 / 추천 계정 / 사유 생성
   ↓
계정 제안.md 같은 문서로 저장
```

## 결론

`vision_analyze`는 Hermes Agent가 이미지를 이해하기 위해 사용하는 도구입니다.

이번 PoC에서는 이 도구를 사용해서 영수증 이미지를 직접 읽고, `계정_샘플.md`에 있는 계정 기준에 맞춰 경비정산 계정을 추천했습니다.

현재 이 환경에서 실제 사용된 비전 모델은 다음과 같습니다.

- **Provider:** `openai-codex`
- **Model:** `gpt-5.5`

하지만 Hermes 설정에 따라 다른 비전 모델로 바뀔 수 있으므로, 정확한 현재 모델은 `resolve_vision_provider_client()`로 확인하는 것이 가장 확실합니다.
