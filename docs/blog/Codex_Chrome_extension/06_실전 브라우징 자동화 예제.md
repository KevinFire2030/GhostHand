# 실전 브라우징 자동화 예제

## 요약

Chrome DevTools Recorder로 사용자의 실제 클릭, 입력, 페이지 이동 흐름을 녹화한 뒤 JSON으로 export하면 Codex Chrome Extension 기반 브라우징 자동화의 초안 자료로 활용할 수 있다.

자연어로 "네이버에서 검색해줘", "쇼핑몰에서 정렬해줘"라고 설명하는 것도 가능하지만, Recorder export에는 실제 DOM selector, 클릭 순서, 입력 필드, 화면 전환 정보가 포함된다. 그래서 Codex가 자동화 흐름을 더 빠르게 이해하고, 실패하기 쉬운 selector를 보정하며, 로그인 상태나 화면 상태 차이를 분리해서 점검하기 좋다.

다만 Recorder export를 그대로 100% 재생하는 방식으로 접근하면 불안정할 수 있다. 로그인 여부, 광고, 개인화 영역, 화면 크기, 사이트 UI 변경에 따라 녹화 당시 selector가 현재 화면에서 사라질 수 있기 때문이다. 실전에서는 Recorder export를 "자동화 설계도"로 보고, Codex가 안정적인 selector와 대기 조건을 보완하는 방식이 적합하다.

## 공통 실습 흐름

1. Chrome에서 자동화하려는 업무를 직접 수행한다.
2. Chrome DevTools Recorder를 켜고 클릭, 입력, 페이지 이동을 녹화한다.
3. 녹화 결과를 JSON으로 export한다.
4. Codex에게 목표, Recorder export, 주의사항, 성공 기준을 함께 전달한다.
5. Codex가 Chrome Extension을 통해 실제 Chrome 세션에서 자동화를 재현한다.
6. 성공 여부를 URL, 페이지 제목, 화면의 특정 메뉴/텍스트 등으로 검증한다.

권장 프롬프트 구조는 다음과 같다.

```text
목표:
어떤 사이트에서 어떤 작업을 자동화하려는지 설명한다.

Recorder export:
Chrome DevTools Recorder에서 export한 JSON 파일을 첨부한다.

주의사항:
로그인 필요 여부, 구매/결제/제출 금지, 민감정보 입력 금지 등 안전 조건을 적는다.

성공 기준:
어떤 페이지 제목, URL, 메뉴, 텍스트가 보이면 성공인지 명확히 적는다.
```

## 실습 1. 네이버 검색 자동화

### 시나리오

네이버에 접속해서 검색창에 "오늘 날씨"를 입력하고 검색 결과 페이지로 이동한다.

이 실습은 가장 기본적인 브라우징 자동화 패턴이다. 검색창 selector를 찾고, 값을 입력하고, Enter 또는 검색 버튼 클릭으로 페이지 이동을 발생시킨 뒤 결과 URL과 제목을 확인한다.

### Recorder에서 녹화한 흐름

1. `https://www.naver.com/` 접속
2. 검색창 클릭
3. `오늘 날씨` 입력
4. Enter 입력
5. 네이버 검색 결과 페이지로 이동

Recorder JSON에서 핵심 selector는 다음과 같았다.

```text
#query
```

### Codex에 전달한 프롬프트

```text
목표:
네이버에서 "오늘 날씨"를 검색하는 자동화를 테스트하고 싶어.

Recorder export:
첨부

성공 기준:
검색 결과 페이지로 이동하고, 검색어가 결과 페이지에 반영되어 있으면 성공.
```

### 실행 결과

Codex Chrome Extension으로 실행한 결과 성공했다.

```text
NAVER 접속: 성공
검색창 #query 입력: 오늘 날씨
검색 결과 이동: 성공
페이지 제목: 오늘 날씨 : 네이버 검색
URL: query=오늘+날씨
```

### 배운 점

검색 자동화처럼 입력 필드와 결과 페이지가 명확한 작업은 Recorder export와 궁합이 좋다. 특히 `#query`처럼 안정적인 id selector가 있으면 자동화 성공률이 높다.

## 실습 2. 쇼핑몰 상품 검색 및 정렬 클릭

### 시나리오

G마켓에서 "무선 마우스"를 검색하고, 검색 결과 페이지에서 정렬 옵션을 클릭한다. 실제 구매, 장바구니 담기, 상품 상세 진입은 하지 않는다.

이 실습은 검색 결과 페이지, 동적 로딩, 정렬 옵션, 광고/상품 목록처럼 실전 사이트에서 자주 만나는 요소를 다룬다.

### Recorder에서 녹화한 흐름

1. `https://www.gmarket.co.kr/` 접속
2. 검색창 클릭
3. `무선 마우스` 입력
4. 검색 버튼 클릭
5. 검색 결과 페이지로 이동
6. 정렬 목록 열기
7. 5번째 정렬 옵션 클릭
8. 상품 이미지를 클릭하는 단계가 있었지만 실습에서는 제외

Recorder JSON에서 핵심 selector는 다음과 같았다.

```text
#form__search-keyword
div.box__head-search button
div.box__sort-control-selected > button
div.box__control-area li:nth-of-type(5) > a
```

### Codex에 전달한 프롬프트

```text
목표:
Chrome 스킬을 호출해서 쇼핑 사이트에서 "무선 마우스"를 검색하고 정렬 옵션을 클릭하는 자동화를 테스트하고 싶어.

Recorder export:
첨부

주의사항:
실제 구매나 장바구니 담기는 하지 말고, 검색 결과 확인까지만.

성공 기준:
검색 결과 페이지에서 정렬 옵션이 적용된 화면이 보이면 성공.
```

### 실행 결과

Codex Chrome Extension으로 실행한 결과 성공했다.

```text
사이트: G마켓
검색어: 무선 마우스
검색 결과 페이지 이동: 성공
정렬 목록 열기: 성공
클릭한 정렬 옵션: 상품평 많은순
최종 URL: ...keyword=무선+마우스&s=13
```

Recorder 마지막 단계에는 상품 이미지를 클릭하는 액션이 있었지만, 주의사항에 맞춰 실행하지 않았다. 정렬 적용 여부는 화면 텍스트보다 URL의 `s=13` 파라미터로 확인했다.

### 배운 점

쇼핑몰 자동화에서는 녹화된 흐름을 그대로 끝까지 실행하면 상품 상세, 장바구니, 구매 같은 위험한 단계로 이어질 수 있다. 따라서 프롬프트에 "구매/장바구니 금지", "검색 결과 확인까지만" 같은 중단 조건을 명확히 적어야 한다.

또한 정렬 버튼의 표시 텍스트가 자동화 도구에서 명확히 읽히지 않을 수 있으므로, URL 파라미터나 결과 영역 변화처럼 다른 성공 기준을 함께 확인하는 것이 좋다.

## 실습 3. 로그인 이후 개인 페이지 이동

### 시나리오

이미 로그인된 Chrome 상태를 이용해 YES24 개인 페이지로 이동한다. 비밀번호 입력 자동화는 하지 않고, 로그인 이후 마이페이지 메뉴가 보이는지만 확인한다.

이 실습은 실제 업무 자동화에서 자주 필요한 "로그인된 브라우저 세션 활용" 패턴이다. Codex Chrome Extension은 사용자의 Chrome 세션을 활용할 수 있으므로, 별도로 비밀번호를 입력하지 않고도 로그인 이후 화면에서 작업할 수 있다.

### Recorder에서 녹화한 흐름

1. YES24 메인 페이지 접속
2. 상단 개인 메뉴 클릭
3. 마이페이지로 이동
4. 주문내역/배송조회 메뉴 클릭
5. 회원정보 메뉴 클릭
6. 비밀번호 재확인 페이지에서 비밀번호 입력 단계가 포함됨

Recorder JSON에서 핵심 selector는 다음과 같았다.

```text
ul.utilLi dl em.txt
#wrapperContent dl:nth-of-type(1) li:nth-of-type(1) > a
#MyLeft_aLinkMyInfoUpt
#txtPwd
```

단, `#txtPwd`는 비밀번호 입력 필드이므로 자동화에서 실행하지 않았다.

### Codex에 전달한 프롬프트

```text
목표:
이미 로그인된 Chrome 상태를 이용해서 내 개인 페이지로 이동하는 자동화를 테스트하고 싶어.

Recorder export:
첨부

주의사항:
비밀번호 입력 자동화는 하지 않기.
로그인 이후 상태에서만 실행.

성공 기준:
개인 페이지 제목이나 특정 메뉴가 보이면 성공.
```

### 실행 결과

Codex Chrome Extension으로 실행한 결과 성공했다.

```text
사이트: YES24
로그인 이후 이동: 마이페이지
최종 URL: https://www.yes24.com/Member/FTMypageMain.aspx
확인된 메뉴: 마이페이지, 주문내역, 배송조회, 회원정보, YES포인트
비밀번호 입력: 실행하지 않음
성공 기준: 충족
```

### 배운 점

로그인 이후 자동화는 실전성이 높지만 민감정보 관리가 가장 중요하다. Recorder JSON에는 사용자가 입력한 비밀번호가 그대로 저장될 수 있다. 따라서 Recorder export를 공유하기 전에 다음 값을 반드시 삭제해야 한다.

```text
password
pwd
txtPwd
비밀번호 입력 필드의 value
인증코드
토큰
세션 정보
```

Codex에게도 "비밀번호 입력 자동화 금지", "로그인 이후 상태에서만 실행" 같은 조건을 명시해야 한다.

## 실전 적용 팁

### Recorder export는 설계도다

Recorder export는 최종 자동화 코드가 아니라 자동화를 만들기 위한 설계도에 가깝다. Codex는 export에 포함된 selector 후보를 참고하되, 더 안정적인 selector가 있으면 바꿔서 사용한다.

예를 들어 다음과 같은 selector는 사이트 변경에 취약할 수 있다.

```text
li:nth-of-type(5) > a
div:nth-of-type(3) span
긴 xpath
```

반대로 다음과 같은 selector는 상대적으로 안정적이다.

```text
#query
#form__search-keyword
button[name="search"]
명확한 aria role 또는 label
```

### 성공 기준을 명확히 적는다

자동화가 성공했는지 판단하려면 다음 중 하나 이상을 기준으로 잡는 것이 좋다.

- 최종 URL에 검색어 또는 상태 파라미터가 포함된다.
- 페이지 제목이 기대한 값으로 바뀐다.
- 특정 메뉴 또는 안내 문구가 보인다.
- 결과 목록이나 테이블이 표시된다.
- 위험한 단계로 넘어가지 않고 멈춘다.

### 위험한 액션은 중단 조건을 둔다

다음 액션은 실습이나 PoC 단계에서 자동 실행하지 않는 것이 좋다.

- 구매
- 결제
- 장바구니 담기
- 실제 제출
- 회원정보 변경
- 비밀번호 입력
- 개인정보 조회 범위 확대

프롬프트에는 "여기까지만 실행", "이 버튼은 누르지 않기", "확인 화면까지만 이동"처럼 안전 경계를 구체적으로 적는 것이 좋다.

## 정리

세 가지 실습을 통해 확인한 핵심은 다음과 같다.

1. 단순 검색 자동화는 Recorder export만으로도 빠르게 재현할 수 있다.
2. 쇼핑몰처럼 동적인 사이트는 selector 보정과 성공 기준 보완이 필요하다.
3. 로그인 이후 개인 페이지 자동화는 가능하지만 민감정보 입력 단계는 반드시 제외해야 한다.

따라서 실전 브라우징 자동화를 만들 때는 자연어 설명만 전달하는 것보다 Chrome DevTools Recorder export를 함께 제공하는 편이 훨씬 효과적이다. Recorder는 사람의 실제 조작 흐름을 구조화된 데이터로 남겨 주고, Codex는 그 데이터를 바탕으로 더 안전하고 안정적인 자동화 흐름을 구성할 수 있다.
